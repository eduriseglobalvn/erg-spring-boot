## 3. Đánh giá độ hoàn thiện và độ rối logic

### 3.1 Độ hoàn thiện (stub / chưa làm / prototype)
- **Stub có chủ đích**: `saveDraft`, `saveAnswer`, `sync` là no-op "legacy compatibility" (`LmsAttemptUseCase.java:141-170`) – server không giữ bản nháp; mọi rủi ro mất bài dồn vào submit (xem (b1)).
- **Chưa làm**: chấm tay essay (B3); vòng đời attempt hết hạn (không auto-close); thư viện tài nguyên trả `progress` và `recent` luôn rỗng (`LearningResourceLibraryReadService.java:125-126`); không có liên kết `Student.authUserId` trong code vận hành (B2) ⇒ luồng học sinh chạy thật phụ thuộc dữ liệu được nạp tay.
- **Prototype/legacy song song**: chấm fallback "đếm câu" (N2), package legacy dựng từ `quiz.getSlides()` với `gradingMode="async"` giả (`LmsResourceQueryUseCase.java:28-34`); `assigned()` fail-open; ngưỡng đậu cứng 50%.
- **Kết luận**: luồng giao bài → làm bài → chấm → điểm **chưa chạy xuyên suốt** với dữ liệu tạo qua API hiện tại (B1+B2+N3 cùng chặn), trong khi các khối riêng lẻ (GradingEngine, idempotency, snapshot policy, conflict detector) khá kỹ. Đây là dấu hiệu từng phần được kiểm bằng unit test với mock nhưng thiếu test tích hợp end-to-end.

### 3.2 Độ rối logic
- **Lớp chuyển tiếp (pass-through)**: `LmsController → LmsOperations → LmsRuntimeUseCase (một dòng mỗi method, LmsRuntimeUseCase.java:32-45) → LmsAttemptUseCase → LmsAttemptService (bọc repository 1:1, LmsAttemptService.java:24-99) → AttemptRepository`. - **Quy tắc trùng lặp, lệch nhau**:
  - Kiểm class scope viết lại ≥4 lần với khác biệt: `LmsAttemptUseCase.java:350`, `LmsStudentReadModelUseCase.java:66-73,77`, `ReportingOperations.java:66` (không kiểm đơn vị), GraphQL `assertAssignmentResponseScope` (có ngoại lệ `assignedBy`).
